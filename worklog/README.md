# 工作留痕

本目录记录每日工作过程。提交时间戳即工作过程的时间锚点。

## 规则

1. **思考底稿完成即提交**：每完成一份设计、调研、方案或会议纪要，立即 `git add` 该文件并提交。
2. **只提交工作产物**：提交前先看 `git status` / `git diff`，不夹带无关改动、临时文件、密钥或大体积二进制。
3. **提交信息**：`docs(worklog): <主题> (YYYY-MM-DD)`；涉及代码时用对应的 `type(scope): summary`。
4. **日报触发**：用户说"休息了""今天到这"时，整理当天进度，写 `worklog/YYYY-MM-DD.md` 并提交。

## 日报结构

```
# YYYY-MM-DD 日报

## 今日目标
## 完成事项
## 关键结论
## 未决问题
## 明日计划
## 相关提交（commit hash）
```

## 约定

- 日报只记录事实：做了什么、决定了什么、还差什么。
- 结论要可追溯：能指向具体文档、代码或提交。
- 不追补规则生效之前的历史。
